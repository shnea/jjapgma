# 기능별 외부 연동 지침

**이 폴더에 기능별 지침을 넣으면 해당 기능은 그 지침으로 구현한다. 지침이 없으면 자체 구현한다.**

현재 포함된 것은 이 안내뿐이며 활성화된 외부 연동은 없다. 로그인·파일·에디터·AI 등의 지침은 사용할 프로젝트에 필요한 것만 넣는다. 자세한 탐색·우선순위·전환 기준은 [외부 연동 적용 규칙](../../../docs/INTEGRATIONS.md)을 따른다.

## 사용 방법

1. 사용할 지침 파일을 이 폴더에 복사한다. 기존 파일명·언어·Markdown 형식을 그대로 사용해도 된다.
2. 실제 소비 프로젝트의 이름·도메인·client ID·필드 매핑을 확인한다. 제공자의 API 계약과 소비자 예시를 구분한다.
3. 에이전트에게 해당 기능의 구현을 요청한다. 별도 “외부 연동 켜기” 요청이나 설정 플래그는 필요 없다.
4. 에이전트는 파일을 탐색해 적용하고 [프로젝트 설정표](../../../docs/PROJECT_SETUP.md)에 선택 근거·남은 설정을 기록한다.

공유 저장소 등 다른 경로를 기준으로 사용할 수도 있다. 이 경우 프로젝트 설정표에 접근 가능한 경로와 적용 범위를 적는다. 특정 PC 경로를 범용 템플릿의 필수 의존성으로 만들지 않는다.

## 파일명 예시

아래는 이름 예시이며 실제 파일이나 활성화 목록이 아니다.

```text
login-service.md
file-service.md
editor.md
외부서비스_ai-agent-api_사용지침.md
payments.md
mail.md
```

README 목록이 실제 파일과 달라도 실제 지침을 확인한다. 파일 이름만 보고 기능을 결정하지 않는다. 참고만 할 문서는 `상태: 참고`, 사용하지 않을 문서는 `상태: 비활성`처럼 명시하거나 `references/`, `archive/`에 구분한다.

## 새 지침을 쓸 때의 짧은 양식

양식은 선택 사항이다. 기존 지침에 이 항목이 없다는 이유로 적용을 거부하지 않는다.

```markdown
# <기능 / 서비스·패키지> 연동 지침

- 적용 기능:
- 외부가 맡을 책임:
- 앱이 계속 맡을 책임:
- 중복 구현하지 않을 기능:
- 제공자 API/SDK·버전·공식 문서:
- 환경별 설정·변수명: 비밀값 제외
- 입력·응답·오류·데이터 형식:
- 필수 의존 지침:
- timeout·재시도·멱등성·실패 동작:
- 기존 데이터 전환·검증:
```

실제 비밀키·운영 개인정보를 넣지 않는다. 문서가 있다고 API를 호출하거나 배포한 것은 아니다. 구현과 검증 결과는 구분해서 기록한다.
