# 파일 서비스 적용

짭그마에서 컴포넌트·템플릿을 작성하는 서식 편집기(`richText`)는 `category=tmp`를 전달합니다. 실제 서비스에 가져간 편집기의 새 업로드는 category를 생략해 default 정책을 사용합니다. 이때 소비 서비스 백엔드도 category를 생략합니다. 본문 JSON의 파일 참조와 `richTextFiles`를 함께 저장하고 프로젝트/개인 템플릿 권한을 검사합니다. 업로드한 본문 첨부는 HTML·Storybook ZIP에 포함되며, 템플릿 재사용은 기존 파일 수명을 연장하지 않습니다. [사용법](RICH_TEXT_EDITOR.md), [실제 서비스 연결](RICH_TEXT_RUNTIME.md).

근거: 사용자가 추가한 [file-service.md](../eocs/agent/integrations/file-service.md). 이전 소비 앱 이름 `mudeora`는 짭그마 프로젝트/페이지에 매핑합니다.

2026-09-16 사용자 확인: 파일 서비스 실연동은 정상 동작합니다. 이번 로그인 연결에서는 기존 설정을 유지하고 외부 업로드를 재실행하지 않았습니다. 아래 응답·보존 분류 상세는 기존 계약 기록이며, 사용자 확인을 모든 오류/보존 시나리오의 검증으로 확대하지 않습니다.

## 책임과 호출

AI 채팅의 참고 이미지도 같은 업로드 프록시와 project_files를 사용합니다. 프로젝트 편집 권한과 실제 이미지 형식·5 MB 상한을 검증하고, n8n에는 기존 공개 원본 다운로드 주소를 전달합니다. 대화 DB에는 fileId·이름·MIME만 저장합니다. 이미지 전달 설정과 모델 검증 범위는 [AI/MCP](AI_MCP.md), [n8n 이미지 연결](N8N_SETUP.md#8-참고-이미지-연결)을 따릅니다.

AI 채팅에서 새로 선택한 이미지는 브라우저에서 최대 1,024px·200 KB 이하로 변환한 파일만 업로드합니다. 이 경우 파일 서비스의 원본은 이미 축소된 파일입니다. 로컬 원본을 먼저 전송하거나 별도 보관하지 않으며 일반 페이지 이미지/파일 업로드에는 이 변환을 적용하지 않습니다. n8n 노드·환경변수·DB 변경은 필요하지 않습니다.

- 외부 `https://file.shnea.kr`: 파일 본문 보관, 미리보기, 다운로드, 보존 정책.
- 짭그마: 세션/CSRF, OWNER·EDITOR 권한, 형식·크기 검사, 업로드 서버 프록시, 프로젝트 fileId 연결, 페이지 Spec 참조 검증.
- 브라우저 → `POST /api/files/upload?projectId=<UUID>` (`file` multipart 단일 파일) → 외부 `POST /files/upload`.
- API multipart는 메모리 버퍼를 사용합니다. Nginx도 업로드 요청을 디스크에 보관하지 않도록 구성합니다. 파일 본문을 DB/볼륨에 저장하지 않습니다.
- `project_files`에는 fileId, 이름, MIME, 크기, 업로더를 저장합니다. 페이지 `props.attachment`에는 fileId/name/mimeType만 남깁니다. 페이지 저장 시 프로젝트에 등록된 참조인지 검사합니다.
- 외부 업로드 성공 후 DB 실패·요소 삭제·응답 유실이면 미참조 파일이 남을 수 있습니다. 자동 재업로드하지 않으며 외부 보존 정책에 맡깁니다. 삭제 API 계약이 없어 임의 API를 만들지 않습니다.

## 설정

| 변수 | 범위 / 동작 |
| --- | --- |
| FILE_SERVICE_BASE_URL | 서버 런타임, 기본 https://file.shnea.kr. 운영은 이 origin만 허용 |
| FILE_SERVICE_BEARER_TOKEN | 서버 전용 JWT. 빈 값이면 설정 안내/503, 로컬 저장 우회 없음 |
| UPLOAD_MAX_BYTES | 서버 런타임, 기본 10485760, 1–10485760. Nginx multipart 제한 11 MiB |

토큰은 `https://bearer.shnea.kr/`에서 별도로 준비해 `.env`에 설정합니다. 브라우저 환경변수·번들·로그에 넣지 않습니다. 개발 Compose도 같은 변수명을 받습니다. 앞단 HTTPS 프록시의 허용 크기도 11 MiB 이상이어야 합니다.

형식: PNG/JPEG/GIF/WebP/PDF/TXT/CSV/JSON. 확장자/MIME과 바이너리 헤더 또는 UTF-8/JSON 내용을 검사합니다. SVG/HTML과 임의 실행 파일은 허용하지 않습니다. 악성코드 검사 엔진이나 완전한 파일 구조 분석은 아닙니다.

## 미리보기·오류

개인 템플릿은 원본 페이지의 편집 권한과 `project_files`를 검사한 뒤 파일 ID·메타데이터를 `template_files`에 복사합니다. 본문은 외부 서비스에 유지합니다. 템플릿 미리보기는 템플릿 소유권으로 인가하고, 다른 프로젝트에 적용할 때 소유권 및 대상 편집 권한을 검사해 `project_files`에 참조를 추가합니다. 원본 프로젝트 삭제와 개인 템플릿 삭제가 이미 복사한 참조를 제거하지 않습니다. 파일 서비스의 공개 URL·보존 정책은 동일합니다.

- 프로젝트 권한/참조 확인 후 외부 preview를 확인합니다. `202`는 준비 중으로 표시하고 최대 5회, 2초 간격 확인 후 수동 재확인을 제공합니다.
- 이미지는 외부 preview URL을 사용합니다. CSP는 `https://file.shnea.kr` 이미지를 허용합니다. 다운로드는 권한 확인 후 외부 URL로 303 이동합니다.
- 외부 URL 자체는 지침상 **공개**입니다. 앱 권한을 외부 파일 비공개 보장으로 설명하지 않습니다. 업로드 UI에도 표시합니다.
- 외부 401 → 앱 503 설정 오류, 413 → 크기 초과, 507 → 저장 공간 부족, 기타/연결 실패 → 안전한 502. 로그에는 연동명/상태만 남깁니다. timeout 20초, 업로드 자동 재시도 없음.
- 외부 보존 정책으로 삭제된 이미지는 만료 가능성과 재확인을 안내합니다.
- Storybook 내보내기는 `GET /api/projects/:projectId/files`에서 이미지 목록을 조회하고 프로젝트/개인 템플릿 파일의 `.../files/:fileId/content`로 본문을 받습니다. 같은 멤버십·파일 참조/템플릿 소유권을 검사하고 기존 외부 `/files/download/:id`만 호출합니다. 파일당 UPLOAD_MAX_BYTES·20초 한도, 리다이렉트 거부, no-store를 적용하고 서버에는 영속 저장하지 않습니다. 브라우저가 ZIP에 복사하므로 내보낸 이미지에는 외부 파일 서비스 접근이 필요하지 않습니다. [Storybook 계약](STORYBOOK_EXPORT.md).

## 계약 상세 확인 기록

1. **Multipart 성공 응답 JSON 예시**: 지침에 envelope가 없습니다. 현재 `{fileId}` 또는 `{files:[{fileId}]}` 단일 파일 응답만 인식하며 나머지는 502입니다. 확인 대기인 호환 가정입니다.
2. **보존 분류 전송 계약**: AI 채팅 이미지는 `category=month`, 서식 편집기 업로드는 `category=tmp`를 브라우저 → 앱 프록시 → 외부 `/files/upload`까지 전달합니다(사용자 요청 2026-09-17/18). 앱은 생략·`month`·`tmp`만 허용하고 임의 값·중복 필드를 거부합니다. 일반 이미지/파일 컴포넌트는 기존처럼 생략하고 외부 기본 정책을 따릅니다. 기존 파일 분류 변경·새 환경변수는 없습니다. 실제 기간별 삭제와 tmp의 정확한 수명은 모의 검증으로 확인하지 않습니다.
3. 자동화 테스트는 격리된 모의 서비스입니다. 실제 연동 정상 동작은 2026-09-16 사용자 확인이며, 만료·외부 크기 제한 등 개별 시나리오를 이번 작업에서 재검증하지 않았습니다.

기존 로컬 저장 구현이 없어 파일 본문 이전은 필요하지 않습니다. `002_project_files.sql`은 테이블 추가입니다. 새 요소/첨부를 저장한 뒤 이전 앱으로 되돌리면 이전 Spec 검증기는 이를 알지 못하므로 페이지 편집 호환성을 확인해야 합니다.
