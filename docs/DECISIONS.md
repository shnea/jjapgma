# 결정 기록

## D-006 — AI 변경 제안과 두 MCP 인증 범위

- 날짜: 2026-09-16. 상태: 채택. 근거: 내장 AI 대화와 개인 로컬 에이전트를 프로젝트 편집에 연결하는 사용자 요청.
- 선택: 기존 API 안의 공통 MCP 도구·검증·제안 서비스를 재사용합니다. n8n은 실행별 사용자/페이지 범위, 개인 연결은 프로젝트별 만료·폐기 가능한 토큰과 읽기/변경 제안 범위를 사용합니다.
- 변경은 제안으로 저장하고 사용자가 미리본 뒤 적용합니다. 기존 revision·트랜잭션·권한을 사용합니다. 미저장 편집은 먼저 저장하며 제안 이후 저장된 변경은 기준 버전과 비교해 병합하거나 사용자가 전체 덮어쓰기를 선택합니다. 검토 이후의 추가 저장은 적용을 거절하고 재확인합니다. 기존 화면은 버전으로 보존합니다. 토큰으로 공유 권한이나 보안 설정을 바꾸는 도구는 제공하지 않습니다.
- 영향: 별도 MCP 서비스나 Provider 직접 호출을 추가하지 않습니다. 기존 n8n 워크플로의 인증·도구 호출 확장은 사용자 작업이며 실제 외부 적용 전 내장 AI는 비활성입니다. [계약](AI_MCP.md), [외부 설정](N8N_SETUP.md).

## D-005 — 삭제된 페이지와 버전 보존

- 날짜: 2026-09-16. 상태: 채택. 근거: 잘못 삭제한 페이지의 버전을 찾아 복원해야 한다는 사용자 요청.
- 선택: 기존 페이지 완전 삭제를 deleted_at 기반 숨김으로 변경. 저장된 버전과 프로젝트 파일 참조를 보관하고 복원 시 새 revision을 생성.
- 권한: OWNER/EDITOR만 삭제된 페이지와 버전에 접근·복원. 프로젝트 자체 삭제의 OWNER 전용 정책은 유지.
- 영향: 이전 완전 삭제 데이터는 백업 없이 복구 불가. 자동 보관 만료와 페이지 영구 삭제는 이번에 제공하지 않음. [상세](PAGE_LIBRARY.md).

- 재검토: CI runner 및 무중단 요구가 구체화되면 자동화.

## D-003 — 외부 인증/AI와 앱의 책임

- 날짜: 2026-09-15. 상태: 채택.
- 근거: 사용자가 제공한 login-service 및 Jjapgma n8n 지침.
- 인증: 외부 login-service; 앱은 서버 세션·callback 검증·내부 사용자/프로젝트 ACL.
- AI: n8n의 /webhook/jjapgma만 Provider 진입점으로 사용. 현재 자연어 응답과 향후 MCP 편집 계약을 분리.
- 영향: mudeora 예시 client 값은 짭그마 등록값으로 매핑. 실제 OIDC 비밀값 없이는 실 연동 완료로 기록하지 않음.
- n8n 외부 수정은 필요한 시점에 사용자에게 작업 내용을 전달. 모델 직접 호출이나 장애 시 자체 구현 우회는 하지 않음.
