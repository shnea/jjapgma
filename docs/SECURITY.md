# 공통 보안

관련 기능을 구현할 때 적용한다. 인증·결제·파일 업로드 같은 기능 자체를 모든 프로젝트에 추가하라는 뜻은 아니다. 자체 구현/외부 연동의 선택은 [연동 적용 규칙](INTEGRATIONS.md)을 따르고 이 문서는 양쪽에 공통으로 적용한다.

## 필수 경계

- 서버에서 모든 입력의 타입·길이·범위를 검증한다. 클라이언트 검증은 사용 편의용이다.
- 인증과 인가를 구분한다. 요청마다 객체 소유권·조직/테넌트 범위·역할을 검사하고, 기본 접근은 거부한다. 화면에서 버튼을 숨기는 것으로 권한을 구현하지 않는다. [OWASP 인가 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
- SQL은 파라미터 바인딩이나 ORM을 사용한다. 사용자 HTML은 필요한 경우 정화하고, 파일 경로·명령 문자열을 직접 이어 붙이지 않는다.
- 업로드가 있으면 크기·형식·소유권을 확인하고 임의 실행을 막는다. 서버가 사용자 URL을 가져오면 내부망·메타데이터 주소와 리다이렉트 우회를 제한한다.
- 오류 응답에 스택·SQL·내부 주소·비밀값을 내보내지 않는다. 민감한 작업은 주체·결과·대상 식별자를 최소한으로 감사 기록한다.
- 로그인·비밀번호 재설정·공개 고비용 API에 요청 제한을 적용한다. 프록시 신뢰 범위를 제한해 위조된 IP 헤더를 신뢰하지 않는다.

## 환경변수와 비밀값

- 실제 프로젝트에서 구성요소별 `.env.example`을 만든다. 변수마다 목적, 필수 여부, 공개/서버 전용, 주입 시점을 적는다. 실제 비밀값 대신 빈 값이나 명백한 예시를 사용한다.
- 시작 시 필수 변수를 검증하고 누락 시 이유를 밝히며 실패한다. 운영에서 `change_me` 같은 기본 비밀번호로 실행하지 않는다.
- 운영 비밀값은 배포 플랫폼의 시크릿 저장소에 두고, 환경별·서비스별 최소 권한으로 분리한다.
- 브라우저 번들·소스맵·Storybook·스크린샷·로그에 비밀값과 실제 개인정보를 넣지 않는다. 프론트 공개 변수는 사용자가 볼 수 있다고 가정한다.
- 로그는 허용할 필드를 골라 기록하고 비밀번호·쿠키·토큰·Authorization 헤더·인가 코드를 제외한다.
- `.gitignore`나 도구별 ignore 파일은 접근 제어가 아니다. 노출된 키는 파일 삭제만 하지 말고 폐기·교체한다.

## 인증이 필요한 경우

- 먼저 로그인 관련 연동 지침을 확인한다. 없으면 요구한 자체 인증을 구현하고, 있으면 지침이 지정한 외부 인증을 연동한다. 외부가 맡은 가입·비밀번호 검증·IdP 발급을 중복 구현하지 않는다.
- 선택한 방식과 앱에 필요한 세션·사용자 매핑을 [프로젝트 설정](PROJECT_SETUP.md)에 기록한다. 업무 권한 검사는 앱에서 유지한다.
- 검증된 인증 라이브러리를 사용한다. 브라우저 세션은 서버가 관리하는 `HttpOnly`, 운영 `Secure`, 적절한 `SameSite` 쿠키를 우선 검토한다.
- 쿠키 인증의 상태 변경 요청에는 CSRF 방어를 둔다. CORS는 CSRF 방어나 인증의 대체가 아니다. 자격 증명을 허용하는 origin은 정확하게 제한한다.
- OAuth/OIDC는 Authorization Code와 PKCE를 우선하고, 선택한 흐름의 state·nonce·issuer·audience·서명·만료 검증을 라이브러리로 수행한다. 허용된 callback과 안전한 상대 return URL만 사용한다. [OWASP OAuth2 지침](https://cheatsheetseries.owasp.org/cheatsheets/OAuth2_Cheat_Sheet.html)
- 사용자 키는 내부 ID로 유지하고 외부 identity는 issuer/제공자와 subject로 연결한다. 같은 이메일만으로 자동 계정 연결하지 않는다.
- 로그아웃·만료·탈퇴·권한 회수 시 세션 처리와 refresh token을 사용하는 경우 회전·재사용 탐지를 정의한다.
- 비밀번호 인증을 직접 제공하면 검증된 적응형 해시, 일회성·만료되는 재설정 토큰, 계정 존재를 노출하지 않는 응답을 사용한다.
- 최소 검증: 정상 로그인, 미인증·권한 없음, 타인의 객체 접근, 로그아웃·만료, 민감정보 비노출. OAuth/OIDC를 사용하면 잘못된 callback/state 등 해당 흐름의 검증도 포함한다.

## 외부 연동의 보안 경계

기능별 계약과 실패·검증 절차는 [연동 적용 규칙](INTEGRATIONS.md) 및 [기능별 지침 폴더](../eocs/agent/integrations/README.md)에 둔다.

- 변경 작업을 무조건 재시도하지 않는다. 결제·작업 생성은 멱등성을 보장한 뒤 재시도한다.
- 웹훅은 원문 서명·허용 시간차를 확인하고 중복·역순·재전달을 처리한다.
- 외부 인증·스토리지·AI를 사용해도 업무 객체와 사용자/조직의 접근 권한은 앱에서 확인한다.
- AI 출력·외부 콘텐츠는 신뢰하지 않고 스키마와 권한을 검증한다. AI에 도구를 연결하면 서버에서 실행 대상을 제한하고 입력 데이터가 실행 권한을 바꾸지 못하게 한다.
