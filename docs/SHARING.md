# 프로젝트 공유

프로젝트 카드의 삭제 버튼 왼쪽 **공유 아이콘**, 또는 편집기 상단의 **공유**에서 전체 이메일과 보기/편집 권한을 선택합니다. 소유자(OWNER)만 공유 목록 조회·추가·권한 변경·취소를 할 수 있습니다. 소유자 변경/제거는 제공하지 않습니다. 페이지별 공유와 실시간 공동 편집은 이번 범위에 포함하지 않습니다.

## 프로젝트 전환과 공유 알림

메인 화면과 편집기의 좌측 상단 선택 상자에서 내 프로젝트와 공유받은 프로젝트로 이동합니다. **전체 프로젝트**는 메인 화면으로 돌아갑니다. 저장하지 않은 편집 내용이 있으면 이동 전에 브라우저가 확인합니다.

상단 종 아이콘에서 **프로젝트가 공유되었습니다** 알림과 읽지 않은 개수를 확인합니다. auto 모드는 실제 계정 연결 시점, email 모드는 수락 시점에 생성합니다. 메일 수락 전에는 초대 메일을 사용합니다. 화면이 활성화되어 있으면 15초마다 확인하며, 창으로 돌아오거나 알림을 열 때도 새로 조회합니다. 새 공유는 프로젝트 선택 목록에도 반영됩니다.

알림을 누르면 읽음으로 저장하고 해당 프로젝트로 이동합니다. **모두 읽음**도 지원하며 새로고침/다른 세션에서도 읽음 상태가 유지됩니다. 공유 취소 후에는 해당 알림을 숨깁니다. 알림은 본인만 조회·수정할 수 있고 최신 100개를 표시합니다.

## 페이지 관리

편집기 페이지 선택 상자 오른쪽은 **+ → 수정(연필)** 순서입니다. 수정 창에서 이름을 저장하거나 페이지를 삭제합니다. 우측 디자인 패널에는 페이지 이름 입력을 표시하지 않습니다. 이름 저장 시 편집 중인 캔버스 내용도 함께 저장합니다.

OWNER/EDITOR만 수정·삭제할 수 있습니다. 삭제 확인 후 일반 목록에서 숨기며 버전 기록은 보관합니다. 다른 페이지가 있으면 그 페이지를 열고, 마지막 페이지를 삭제하면 페이지 생성 화면을 표시합니다. **삭제된 페이지** 버튼에서 원하는 버전을 미리 보고 복원합니다. 다른 사용자가 저장한 최신 revision과 다르면 삭제를 거부합니다. [복원·템플릿·테마](PAGE_LIBRARY.md).

## 승인 방식

| 변수 | 의미 |
| --- | --- |
| SHARE_APPROVAL_MODE | `auto`(기본): 메일 없이 즉시 공유. `email`: 초대 메일의 링크로 로그인 후 수락 |
| VERIFY_EMAIL_TTL_SECONDS | 메일 초대 유효시간. 기본 86400초, 60~604800초. 로그인 이메일 인증용이 아님 |
| NOTIFY_API_URL | 전체 발송 endpoint. 기본 https://notify.shnea.kr/v1/notifications |
| NOTIFY_API_TOKEN | 서버 전용 Bearer Token. `notify:send` scope 필요 |
| REFRESH_TOKEN_ENCRYPTION_KEY | 기존 세션 키와 함께 초대 메일 재시도 본문도 암호화. 32바이트/64자리 hex |

`.env`를 바꾼 뒤 개발 환경은 `docker compose -f compose.dev.yaml up -d --no-deps --force-recreate --wait api nginx`로 적용합니다. 운영은 [운영 가이드](OPERATIONS.md)를 따릅니다. email 모드는 notify 토큰이나 암호화 키가 없으면 시작 시 실패합니다. auto 모드는 notify를 호출하지 않습니다.

초대를 만든 당시 승인 방식을 저장하므로 설정 변경이 기존 메일 초대를 자동 승인하지 않습니다. 미가입자도 이메일로 미리 추가할 수 있습니다. auto 초대는 해당 사용자의 첫 로그인 또는 프로젝트 목록 조회 때 연결되고, email 초대는 명시적인 수락 전까지 접근할 수 없습니다.

## 이메일과 계정

2026-09-16 사용자가 login-service의 이메일 소유 확인을 보장한다고 확인했습니다. 검증된 ID 토큰의 이메일을 사용하고, 없으면 서버에서 `/userinfo`를 호출해 `sub`가 토큰의 사용자와 같은지 확인합니다. 명시적인 `email_verified=false`나 잘못된 이메일은 공유 연결에 사용하지 않습니다. 이메일을 확보하지 못해도 기존 로그인은 유지합니다.

이메일은 공백 제거·소문자로 정규화하며 `+태그`와 `.`을 임의 제거하지 않습니다. 표시명은 이메일의 `@` 앞부분이고, 공유 관리에서는 전체 이메일도 표시합니다. 기존 사용자는 다시 로그인하거나 세션이 갱신되면 이름과 이메일이 업데이트됩니다.

계정 식별은 계속 issuer+sub, 권한은 내부 사용자 ID를 기준으로 합니다. 같은 이메일의 여러 계정을 병합하거나 임의 선택하지 않습니다. 이미 연결한 권한은 이메일 변경 후 다른 계정으로 이전하지 않습니다. 개발 우회 계정은 실제 OIDC 계정과 분리하며 기존 개발 프로젝트도 자동 이전하지 않습니다.

## 메일 계약과 실패 처리

적용 지침: [notify 서비스 연동](../eocs/agent/integrations/notify_서비스_연동지침.md). 외부 서비스는 EMAIL 발송을 담당합니다. 앱은 초대·수신 계정·권한·수락·취소·유효기간을 담당하며 별도 SMTP를 구현하지 않습니다.

- `POST NOTIFY_API_URL`, Bearer 인증, `channel=EMAIL`, `to.email`, `subject`, HTML `content`를 전송합니다.
- 멱등 키는 `notify:email:project-invitation:<초대 UUID>:created:v1`입니다. 실패 후 **메일 요청 재시도**는 기존 본문과 키를 그대로 사용합니다. 자동 반복 재시도는 하지 않습니다.
- `200`/`202`와 알림 ID를 받으면 **메일 발송 요청 접수**로 표시합니다. 실제 배송 여부를 확인할 조회/콜백 계약은 없으므로 발송 완료라고 표시하지 않습니다.
- 외부 오류/인증 오류/timeout/잘못된 응답은 요청 실패로 기록합니다. 초대는 대기로 남고 권한은 부여하지 않습니다. 설정 수정 후 관리자가 재시도할 수 있습니다.
- 접수된 메일을 다시 보내려면 기존 초대를 취소하고 새로 추가합니다. 새 초대는 새 링크·멱등 키를 사용합니다.
- 초대 링크는 `/invitations#<난수>`입니다. fragment를 탭의 sessionStorage에 보관한 뒤 주소에서 제거해 로그인 왕복을 이어갑니다. 인증 토큰은 저장하지 않습니다. 서버에는 토큰 해시와 재시도용 암호화 메일 본문만 보관하며 수락/취소 시 본문을 지웁니다.
- 링크 열기나 미리보기로 수락되지 않습니다. 로그인된 대상 계정의 CSRF 검증을 통과한 수락 요청만 권한을 부여합니다. 취소/만료된 링크는 거부합니다.

공유 취소·권한 변경은 다음 API 요청부터 적용합니다. 이미 내려받은 산출물이나 외부 file-service의 공개 URL을 회수하는 기능은 아닙니다. 추가·권한 변경·취소·자동 연결·수락·메일 접수 결과를 감사 기록에 남깁니다.

## 데이터와 검증

`003_project_sharing.sql`은 기존 사용자에 선택적 email을 추가하고 project_invitations를 생성합니다. 기존 데이터나 멤버십은 삭제하지 않습니다. API는 OWNER와 EDITOR를 구분하며 프로젝트 삭제도 OWNER만 허용합니다.

`004_share_notifications.sql`은 사용자별 알림과 읽음 상태를 저장하고 기존 수락된 공유 중 현재 멤버십이 유지되는 공유를 알림으로 채웁니다. 외부 notify는 메일 발송을 담당하고, 알림함은 앱이 관리합니다. 별도 환경변수는 추가하지 않습니다.

자동화 검사는 격리 DB와 notify 계약 fixture를 사용합니다. 실제 수신자 메일 발송은 별도이며, 이번 개발 검사에서는 외부 메일을 보내지 않습니다.

2026-09-16 사용자가 실제 공유 이메일 정상 동작을 확인했습니다. 자동화 검사의 notify 응답은 계속 모의 계약이며 실제 메일을 추가 발송하지 않습니다. 최신 검사·배포 결과는 [진행 기록](PROGRESS.md)을 따릅니다.
