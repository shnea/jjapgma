# UI·Storybook 지침

현재 웹은 React/Vite와 `@storybook/react-vite`를 사용합니다. **앱과 Story가 같은 컴포넌트·스타일·Provider를 사용해야 합니다.** 실제 설정은 `apps/web/.storybook/`, 명령은 [개발 가이드](DEVELOPMENT.md)가 기준입니다.

## 구현

- 관련 [연동 지침](INTEGRATIONS.md), 기존 컴포넌트·호출부·Story부터 확인합니다. 기존 UI 재사용이나 작은 variant 추가를 우선합니다.
- 공통 UI는 `apps/web/src/components/`, 기능 UI는 해당 `features/`에 둡니다. 한 번 쓰는 wrapper나 배치까지 공통화하지 않습니다.
- 앱 토큰은 `styles/tokens.css`, 사용자 페이지 테마는 UI Spec·공통 렌더러가 담당합니다. 두 책임을 혼합하거나 새 디자인 체계를 중복 생성하지 않습니다.
- 기존 화면을 다듬을 때는 제품 동작과 사용자 편집값을 보존합니다. 사용자가 시각적 개선을 요청하면 오류가 없는 화면도 타이포그래피·여백·색·구성을 개선하고 전후 화면으로 확인합니다. 새 디자인 스킬의 취향을 제품 요구사항으로 취급하지 않습니다.

## Story

| 변경 | 필요한 사례 |
| --- | --- |
| 공통 UI | 실제 컴포넌트를 import한 기본·의미 있는 상태 Story |
| 복잡한 기능 UI | 오류·빈 데이터·긴 내용·권한 등 독립 검증 가치가 있는 상태 |
| 단순 문구·일회성 배치 | 별도 Story를 만들지 않고 기존 화면에서 확인 |

Story는 컴포넌트 가까이에 둡니다. 날짜·네트워크·랜덤 데이터를 재현 가능하게 만들고 실제 계정·고객 데이터를 사용하지 않습니다. 성공·실패·지연은 네트워크 경계에서 모의 처리하며 사용자 상호작용을 무효화하지 않습니다.

## 검증

- 작은 화면·데스크톱·긴 내용에서 넘침, 잘림, 조작 영역을 확인합니다. 에디터 전체의 휴대폰 조작과 사용자가 만든 페이지의 모바일 미리보기는 다른 범위입니다.
- semantic HTML·입력 label·키보드·보이는 focus·텍스트 대비·오류 안내를 확인합니다. Dialog는 focus 진입/복귀·trap·Escape·처리 중 닫기 동작을 검사합니다.
- 바뀐 동작을 `tests/stories/`에서 확인하고 자동 접근성 검사와 실제 키보드·화면 확인을 함께 합니다. 자동 검사 통과를 접근성 전체 보장으로 표현하지 않습니다.
- 라우팅·저장·권한·외부 연결은 앱 E2E/API에서 확인합니다. Story만 통과시키려고 앱 동작을 단순화하지 않습니다.
- 공통 렌더러 변경은 캔버스·미리보기·HTML/Storybook ZIP의 해당 흐름도 검증합니다.
- 별도 시각 회귀 서비스·공개 Storybook 배포·새 테스트 runner는 기본 요구사항이 아닙니다. 기존 Docker/Playwright 검증을 재사용합니다.
