# Storybook 내보내기

편집기 → 내보내기 → 스토리북 내보내기로 독립 실행 ZIP을 받습니다. JSON 요약 예제가 아니라 편집기와 같은 NodeRenderer·스타일을 실행합니다.

## 포함 범위

- 현재 프로젝트의 삭제되지 않은 모든 페이지. 현재 페이지는 버튼을 누른 시점의 이름·미저장 명세를 사용하고 나머지는 저장된 버전을 가져옵니다.
- Registry에 등록된 모든 기본 컴포넌트. 자식 영역, 캐러셀·단계 화면에는 예시 내용을 넣고 팝업에는 열기 버튼을 함께 제공합니다.
- 모든 공식 템플릿과 현재 계정의 모든 개인 템플릿. 컴포넌트·템플릿을 추가하면 다음 내보내기에 자동 반영됩니다.
- 프로젝트에 등록된 전체 이미지와 페이지·템플릿에서 참조하는 이미지·첨부파일. 프로젝트에 올라갔지만 현재 페이지에 배치하지 않은 이미지도 포함합니다. 표 이미지와 캐러셀 자식 이미지도 수집합니다.

Storybook에서 프로젝트 / 컴포넌트 / 공식 템플릿 / 개인 템플릿 / 이미지로 구분합니다. 각 화면의 Desktop·Tablet·Mobile Story와 Controls의 명세를 사용할 수 있습니다. 이미지 목록에서는 파일을 따로 내려받을 수 있습니다.

## 실행

Node.js 24 환경에서 ZIP을 풀고 실행합니다.

```sh
npm install
npm run storybook
```

http://localhost:6006 에서 확인합니다. 정적 배포 파일은 `npm run build-storybook`으로 `storybook-static/`에 생성합니다. 의존성 버전은 짭그마의 검증된 고정 버전에서 가져옵니다.

| 경로 | 내용 |
| --- | --- |
| `.storybook/` | React Vite 설정, 공통 스타일, 분류 순서 |
| `src/*.stories.jsx` | 각 화면의 실제 CSF Story |
| `src/data/` | 수정 가능한 UI 명세와 로컬 파일 매핑 |
| `renderer/` | 앱과 같은 렌더러의 ESM 번들·CSS |
| `public/assets/` | 복사한 이미지·첨부파일 |
| `manifest.json` | 포함된 페이지·컴포넌트·템플릿·이미지 건수 |

설치·빌드 이후 화면과 파일은 짭그마 로그인이나 외부 파일 서비스 연결 없이 열립니다. 폼·메뉴·팝업·캐러셀 등 미리보기 동작은 유지하지만 로그인·AI·결제·DB 저장·업로드 서비스가 자동 연결되지는 않습니다. 외부 링크는 명세에 입력한 주소를 유지합니다.

## 파일과 실패 처리

파일 서비스 지침을 유지합니다. 서버는 기존 프로젝트 멤버십/파일 참조 또는 개인 템플릿 소유권을 확인하고 설정된 파일 서비스의 다운로드 경로만 읽습니다. 리다이렉트를 따라가지 않고 서버 업로드 토큰을 ZIP에 포함하지 않습니다. 본문은 요청 중 메모리에서만 처리하며 앱 DB·볼륨에 저장하지 않습니다.

한 파일은 기존 `UPLOAD_MAX_BYTES`, 내보내기 전체 파일은 250 MiB 이내입니다. 만료·권한 없음·파일 서비스 실패·렌더러 누락은 오류로 표시하고 불완전한 ZIP을 다운로드하지 않습니다. 직접 입력한 외부 이미지 주소는 브라우저 CORS 정책에 따라 실패할 수 있으며 누락을 숨기지 않습니다.

공식 자료: [CSF](https://storybook.js.org/docs/api/csf), [정적 파일 포함](https://storybook.js.org/docs/api/main-config/main-config-static-dirs). 실제 내려받은 ZIP의 빌드·이미지·Story 렌더링 검사는 `tests/e2e/storybook-export.spec.ts`, 파일 접근·크기 제한은 `tests/api/files.test.mjs`에서 검증합니다.
