# 내 계정과 AI 사용량

상단 아바타에서 `/account`로 이동한다. 편집기의 MCP 연결은 버전 버튼 왼쪽에 있다. 페이지가 없는 프로젝트에서도 MCP 연결 버튼을 제공한다.

## 닉네임

- 기본 이름은 기존과 같이 이메일의 `@` 앞부분이다. 이메일 없는 개발 계정은 기본 표시명을 사용한다.
- 닉네임은 공백 제거 후 1–40자, 제어문자 금지, 중복 허용이다. 빈 입력 또는 ‘기본 이름 사용’은 `null`로 초기화한다.
- 로그인 서비스의 신원·이메일을 변경하지 않는다. `users.nickname`을 따로 저장하여 OIDC 재로그인/토큰 갱신의 기본 이름 변경에 덮어쓰이지 않는다. 공유 멤버 목록에도 닉네임을 표시한다.
- 세션 인증과 CSRF를 통과한 사용자만 본인 프로필을 수정한다. 타인의 사용자 ID를 입력받지 않는다.

## 사용량

- 오늘/이번 달/전체 합계와 요청별 시각·모델·상태·입력/출력/총 토큰을 표시한다. 기간은 Asia/Seoul 기준이다.
- 요청별 표의 입력·출력·합계는 제목과 숫자를 같은 오른쪽 기준으로 정렬하고 열 사이 구분선을 둔다. 합계는 배경과 굵기로 구분하며 작은 화면에서는 표 내부를 가로 스크롤한다.
- n8n이 전달한 **실제 모델 사용량**만 합산한다. 모델을 여러 번 호출한 요청은 호출별 기록을 합산하며 실패한 요청도 토큰을 사용할 수 있다.
- 정보가 없으면 미집계, 일부 호출만 확인되면 부분 집계다. 확인되지 않은 사용량을 0 또는 추정값으로 기록하지 않는다. 완료 여부와 사용량 집계 여부는 별개다.
- 외부 개인 MCP 클라이언트의 자체 모델 호출, 기능 도입 전 요청은 알 수 없다. 가격/비용 계산은 제공하지 않는다.
- `ai_usage_runs`는 AI 요청 수락 트랜잭션에서 생성한다. 사용자 FK만 두어 페이지/프로젝트 삭제에도 개인 집계를 유지한다. 대화 본문·이미지·프로젝트 이름은 복사하지 않는다.
- `ai_usage_calls`는 `(run_id,call_id)`로 중복 방지한다. 같은 호출·값의 재보고는 성공, 다른 값 또는 완료 후 새 호출은 409다. 요청당 최대 200개 호출, 토큰 수는 비음수 정수다.

## 연동 계약

웹훅 요청에 `usageReport: { url, token }`이 추가된다. 토큰은 요청별 무작위 값이며 DB에는 해시만 저장하고 7일 동안 해당 요청의 사용량 보고에만 쓴다. MCP/세션 권한은 없다. 모델 Prompt에 이 값을 넣지 않는다.

`POST /api/ai/usage/:runId`, `Authorization: Bearer <usageReport.token>`:

```json
{
  "complete": true,
  "calls": [
    { "id": "execution:node:iteration:output", "model": "provider/model", "inputTokens": 120, "outputTokens": 30, "totalTokens": 150 }
  ]
}
```

`complete=true`는 모든 모델 호출의 실제 사용량이 포함되었을 때만 쓴다. 호출 ID는 재전송에도 동일해야 한다. `model`과 `totalTokens`는 생략 가능하며 합계 생략 시 입력+출력을 사용한다. n8n 웹훅의 JSON 응답에 동일 구조의 `usage`를 넣어 동기 보고할 수도 있다. 잘못된 사용량 때문에 정상 답변까지 실패시키지는 않고 미집계로 남긴다. 중복 집계를 막기 위해 두 경로를 동시에 설정하지 않는다.

기존 AI Agent 출력에 사용량이 없다면 [별도 n8n 수집 설정](N8N_USAGE_SETUP.md)을 적용한다. 사용자 관리 n8n의 변경과 실제 모델 사용량 확인은 앱의 모의 테스트와 별도다.

## API와 마이그레이션

- `PATCH /api/account/profile`: `{nickname:string|null}` → `{nickname,displayName}`. 세션/CSRF 필수.
- `GET /api/account/usage?offset=0`: 본인 요약과 최근 20개 내역, `hasMore`, `timeZone`. 세션 필수.
- 마이그레이션 `009_profile_usage.sql`은 닉네임과 독립 집계 테이블을 추가한다. 기존 데이터를 삭제하거나 이름을 덮어쓰지 않는다. 롤백은 이전 앱 이미지로 복귀하고 추가 열/테이블을 유지하면 된다.

적용 지침: 외부 AI는 기존 ai-agent-api 지침에 따라 n8n gateway를 유지한다. 앱은 신원/인가, 사용량 수신 검증·중복 방지·개인 조회를 담당하며 모델을 직접 호출하지 않는다. 새 환경변수는 없다.
