# 페이지 복원·템플릿·테마

## 삭제와 복원

페이지 선택 상자 옆 연필에서 삭제하면 일반 목록에서 숨기고 저장된 버전은 보관합니다. **삭제된 페이지** 아이콘에서 페이지와 복원할 버전을 선택하고 미리보기를 확인한 뒤 복원합니다. 마지막 페이지를 삭제해도 이 버튼은 남습니다.

- OWNER/EDITOR만 삭제 목록·삭제된 페이지 버전 조회·복원을 할 수 있습니다. VIEWER와 비멤버는 서버에서 차단합니다.
- 복원은 선택한 버전의 이름·명세·테마를 같은 페이지 ID에 복사하고 현재 revision+1로 저장합니다. 이전 버전은 변경하지 않습니다. 삭제·복원은 최신 revision과 현재 상태를 확인하고 감사 기록을 남깁니다.
- 삭제 전 저장하지 않은 변경은 버전으로 남지 않습니다. 005 마이그레이션 이전에 완전히 삭제된 페이지는 백업이 없으면 앱에서 복원할 수 없습니다.
- 삭제된 페이지는 자동 만료·영구 삭제하지 않습니다. 프로젝트 전체 삭제는 기존처럼 관련 데이터까지 삭제하며 이번 페이지 복원 범위에 포함하지 않습니다.
- 삭제 목록은 최신 500개, 버전은 50개씩 조회하며 **이전 버전 더 보기**로 더 오래된 기록을 확인합니다. 일반 프로젝트 페이지 수에는 삭제된 페이지가 포함되지 않습니다.
- 파일 참조는 유지합니다. 외부 file-service의 보존 기간이 끝난 파일 본문까지 복구하는 기능은 아닙니다.

기존 7개 ID를 보존하고 총 22개를 제공합니다. 목록과 순서는 `packages/ui-spec/src/templates.ts`의 공통 Registry, 추가 생성기는 `template-builders.ts`에서 관리합니다. 서버는 알려진 ID만 받아 새 노드 ID로 생성하고 첫 버전을 저장합니다. 일반 요소처럼 편집할 수 있고 모바일에서는 다열 그리드와 가로 영역을 세로로 바꿉니다. 검색·필터·페이징은 예시 데이터에서 동작하지만 로그인·제출·결제 등 실제 업무 API는 자동 연결하지 않습니다. 로그인 템플릿은 짭그마 자체의 login-service 연동을 대체하지 않습니다.

새 페이지 선택 창과 공식 템플릿 패널은 같은 5개 그룹 순서와 분류 버튼, 이름·설명·ID 검색을 사용합니다. 등록/수정은 입력 폼, 가입/결제/신청 완료는 처리 완료 템플릿을 재사용해 중복을 줄였습니다. 개인 템플릿과 기존 저장 페이지는 변경하지 않습니다.

### 함께 제공하는 컴포넌트

- **차트·그래프 (`chart`)**: 세로 막대·가로 막대·꺾은선·영역·도넛 전환, 항목 이름/값/단위 편집, 최대 24개 비음수 값. 빈 데이터·전체 0도 처리하고 색상 외에 텍스트 값 목록을 제공합니다. 캔버스·미리보기·HTML ZIP에서 같은 렌더러를 사용합니다.
- **그리드 (`grid`)**: 팔레트 클릭/드래그로 추가하면 테두리가 있는 컨테이너 4개를 2×2로 제공합니다. 각 칸을 선택해 요소를 추가합니다. 선택한 그리드 위의 행·열 +/−는 실제 영역을 조절하며 저장/실행 취소 대상입니다. 내용이 있거나 잠긴 칸은 축소할 수 없습니다. 기본 구조는 모든 기기에 공통이고 모바일은 1열로 표시합니다. 속성 패널에서 모바일 열 수만 바꾸면 내용 추가/삭제 없이 배치만 달라집니다. 기존 그리드/템플릿 내용을 빈 칸으로 교체하지 않습니다.
- **단계별 입력 (`wizard`)**: 자식 컨테이너/카드 하나가 한 단계이며 요소 이름이 단계 제목입니다. 이전/다음/완료, 단계 사이 입력 유지, 현재 단계의 기본 입력 검증을 제공합니다. 편집 중 레이어에서 하위 요소를 선택하면 그 단계를 표시합니다. 미리보기 입력은 브라우저 내 상태이며 실제 제출·서버 저장은 연결하지 않습니다.
- **검색 입력 연결**: `input`을 검색 유형으로 바꾸고 대상 테이블 또는 메뉴를 선택합니다. `searchTargetId`로 연결하며 템플릿 복제 시 대상 ID도 새 ID로 바꿉니다. 목록 관리는 기존 검색 입력을 테이블에 연결해 중복 검색창을 만들지 않습니다.

차트·단계별 입력은 템플릿 전용 구현이 아니라 팔레트, Inspector, 공통 명세, MCP에서 독립적으로 제공합니다. 기존 페이지에는 새 선택적 속성을 강제로 넣지 않으며 이번 확장에 DB 마이그레이션·환경변수 추가는 없습니다.

목록 관리의 검색/추가 영역은 하단 정렬을 바탕으로 실제 입력칸의 세로 중앙에 버튼을 맞춥니다. 라벨 높이는 기준에서 제외하며 입력칸보다 낮은 버튼은 높이 차이의 절반만큼 아래 여유를 둡니다. 실제 높이를 관찰하므로 라벨 표시·위치와 입력 글자 크기가 바뀌어도 대응합니다. 모바일 세로 배치에는 이 보정을 적용하지 않습니다.

## 편집 중 템플릿 사용

레이어 오른쪽 **템플릿** 탭에는 **공식 템플릿 / 내 템플릿**이 있습니다. 이름·분류 검색과 미리보기를 제공하며, **화면에 추가**는 선택한 컨테이너(일반 요소 선택 시 부모)에 템플릿 전체를 하나의 묶음으로 넣습니다. 기존 내용과 현재 페이지 테마는 유지하고 새 노드 ID를 부여합니다. 한 번의 실행 취소로 추가를 되돌릴 수 있으며 페이지 저장 시 일반 요소와 함께 기록됩니다. 잠긴 영역·보기 전용·충돌 상태에서는 삽입을 차단합니다.

공식 템플릿은 `packages/ui-spec/src/templates.ts`의 `templateDefinitions`에 메타데이터, 생성 함수, 테마 번호를 함께 등록합니다. 새 페이지 선택 창과 편집 패널이 같은 목록을 사용합니다. 생성기는 매번 독립 노드 ID를 만들고 공통 명세 검증을 통과해야 합니다.

워크스페이스 메인은 최상위 네 방향 안쪽 여백과 간격이 0입니다. 공식 메인을 **페이지 루트에 삽입**할 때는 부모 페이지의 기본/태블릿/모바일 여백과 간격도 0으로 맞춰 헤더·사이드바가 가장자리에 붙습니다. 콘텐츠와 테마는 유지하고 이 변경도 삽입과 함께 한 번에 실행 취소됩니다. 하위 컨테이너 삽입과 개인 템플릿에는 이 규칙을 적용하지 않습니다. 이미 저장한 템플릿 사본의 배치는 자동 변경하지 않습니다.

**내 템플릿 → 현재 화면 저장**에서 이름을 입력하면 현재 편집 중인 화면 전체를 개인 스냅샷으로 저장합니다. 저장하지 않은 페이지 수정도 포함하며 원본 페이지와 이후 동기화하지 않습니다. 현재는 화면 전체 저장을 지원하고 선택 요소만 저장하는 기능은 없습니다.

- 계정별 최대 100개. 목록·상세·이미지 미리보기·사용·삭제는 소유자만 접근합니다. 프로젝트 공유로 개인 템플릿 목록이 공유되지는 않습니다.
- 생성 시 원본 페이지의 OWNER/EDITOR 권한과 명세·파일 연결을 서버에서 확인합니다. 사용 시 대상 프로젝트의 OWNER/EDITOR 권한을 다시 확인합니다.
- 이미지·첨부 본문은 file-service에 그대로 두고 검증한 파일 ID·메타데이터만 개인 템플릿에 보존합니다. 다른 프로젝트에서 사용할 때 해당 프로젝트에 파일 참조를 추가합니다. 따라서 원본 프로젝트 삭제/접근 해제 후에도 저장한 개인 복사본은 남습니다. 외부 파일 자체의 만료까지 방지하지는 않습니다.
- 사용 API는 파일 연결과 명세 반환을 담당합니다. 캔버스 삽입 후 페이지 저장은 기존 편집 흐름이며, 실행 취소해도 연결된 파일 참조를 자동 삭제하지 않습니다.
- 내 템플릿을 삭제해도 이미 삽입한 페이지와 그 파일 참조는 유지합니다. 템플릿 삭제는 복원 기능이 없으므로 대화상자에서 확인합니다.
- 미리보기는 저장 당시 테마를 사용합니다. 현재 페이지에 추가한 요소는 현재 페이지 테마를 따르며 직접 지정한 요소 스타일은 유지됩니다.

## 디자인 패널 너비

우측 패널 기본 너비는 380px입니다. 왼쪽 경계 드래그 또는 경계에 포커스 후 좌우 방향키로 조절합니다. Home/End는 최소/최대, 두 번 클릭은 기본 너비로 복원합니다. 300–560px 범위에서 캔버스 공간을 고려해 제한하며 브라우저에 선택 너비를 기억합니다. 좁은 창에서는 실제 너비를 줄이고 다시 넓히면 선호 너비로 돌아옵니다. AI 탭은 [채팅/MCP](AI_MCP.md)에 연결됩니다.

공식 채팅 템플릿은 팔레트의 `채팅` 요소를 사용합니다. 속성 패널에서 제목·입력 안내·예시 메시지(최대 50개)·좌우 위치·시간·대기 상태를 편집합니다. 미리보기와 HTML 내보내기에서 Enter로 예시 메시지를 추가하고 Shift+Enter로 줄바꿈합니다. 메시지 본문과 입력창은 내부 공간을 나누어 대화만 스크롤합니다. 이 요소는 화면 설계와 미리보기용이며 실제 n8n 연결·대화 저장은 편집기의 AI 탭 기능입니다.

## 화면 테마 설정

레이어 최상위 **화면**을 선택하면 우측 디자인 패널에 **화면 테마**가 나타납니다. 포레스트·오션·바이올렛·샌드 프리셋과 사용자 색상, 고딕/명조/고정폭 글꼴, 모서리, 간격을 제공합니다. **기존 스타일**은 테마 설정을 제거합니다.

- 테마는 프로젝트 전체가 아닌 현재 페이지에 적용합니다. 명시적 요소 스타일과 반응형 값이 테마 기본값보다 우선합니다. 기존 페이지의 직접 지정된 흰 배경·간격 등도 보존합니다. **화면의 테마 기본값 사용**은 루트 화면의 배경·글자색·모서리·여백·간격과 해당 반응형 지정값을 지워 테마를 따르게 합니다. 하위 요소의 지정값은 유지하며 실행 취소가 가능합니다.
- 테마가 설정된 페이지에서 새로 추가하는 영역·카드는 기본 색상·모서리·간격을 상속합니다. 기존 요소를 테마 변경 시 일괄 덮어쓰지 않습니다.
- 저장·새로고침·실행 취소·다시 실행·버전 복원에 테마를 포함합니다. 캔버스와 미리보기, HTML ZIP은 같은 NodeRenderer와 테마 CSS를 사용합니다. JSON/Storybook ZIP의 원본 명세에도 포함합니다. 기존 Storybook ZIP은 명세 요약 화면이며 HTML ZIP과 같은 완전한 렌더러 패키지가 아닙니다.
- schemaVersion 1에 선택적 `theme`를 추가해 테마 없는 기존 명세와 호환합니다. 서버는 색상·글꼴 enum·수치 범위를 검증합니다. 외부 폰트·임의 CSS URL을 테마로 받지 않습니다.

## 연동과 데이터 전환

현재 `eocs/agent/integrations/`에는 삭제 복원·템플릿·테마를 외부로 맡기는 적용 지침이 없습니다. AI 지침의 Template Registry/Theme/MCP 항목은 향후 읽기 기능이며 외부 구현 계약이 아닙니다. 이번 기능은 기존 앱 명세와 DB에서 구현하고 외부 AI를 호출하지 않습니다. 이미지 본문은 기존 file-service 책임을 유지합니다.

`005_page_trash.sql`은 `pages.deleted_at`과 삭제 목록 인덱스만 추가하며 기존 페이지/버전/파일 참조를 보존합니다. 새 환경변수는 없습니다. 이전 앱 이미지는 삭제 상태를 이해하지 못하므로 이 마이그레이션 이후에는 삭제 상태를 지원하는 이미지로 복구해야 합니다.

`006_personal_templates.sql`은 `personal_templates`, `template_files` 테이블만 추가합니다. 이전 데이터 변경이나 파일 본문 복제는 없습니다. 이전 앱 이미지로 되돌려도 테이블은 보존하고, 개인 템플릿 기능은 다시 지원 버전을 적용하면 사용할 수 있습니다. 환경변수 추가는 없습니다.
