# 서식 편집기 사용법

`@shnea/blocknote` 0.1.5를 사용하는 `서식 편집기(richText)` 컴포넌트입니다. 문서·공지·도움말·게시글 본문에 적합합니다. 짭그마 전체 화면 편집기를 대체하지 않으며, 본문 내부 블록은 짭그마 레이어와 별개로 관리합니다.

## 시작하기

1. 컴포넌트 목록의 **기본 → 서식 편집기**를 추가하거나 공식 **문서 작성**, **공지·안내 문서** 템플릿을 선택합니다.
2. 컴포넌트를 선택하고 디자인 속성의 **본문 편집**을 누릅니다.
3. 글자를 선택해 굵기·기울임·색·글꼴·크기를 변경합니다. `/`로 제목·목록·체크리스트·표·이미지 등 블록을 추가합니다. Markdown 붙여넣기는 패키지의 기본 블록 변환을 사용합니다.
4. **본문 적용**으로 화면 명세에 반영한 뒤 상단 **저장** 또는 **Ctrl/Cmd+S**로 서버에 저장합니다. 실행 취소/다시 실행도 지원합니다. **취소**는 본문 변경을 버립니다. 업로드가 이미 끝난 파일의 외부 보관은 서비스 정책을 따릅니다.

캔버스에서는 읽기 상태로 표시합니다. 미리보기의 **편집기 · 입력 체험** 모드는 입력을 시험하는 용도이며 변경 내용을 저장하지 않습니다. **뷰어 · 읽기 전용**은 공지·문서 표시용입니다. 실제 게시글 등록·발행·업무 API는 자동으로 연결되지 않습니다.

## 디자인 속성과 본문 서식

| 위치 | 변경할 수 있는 내용 |
| --- | --- |
| 디자인 속성 → 내용 | 표시 모드, 기본 글꼴(고딕/명조/고정폭), 뷰어 이미지 확대, 본문 편집 |
| 공통 디자인 속성 | 폭·높이, 반응형 크기, 여백, 배경·글자색, 테두리·모서리, 기본 글자 크기·행간 |
| 본문 선택 도구 | 선택한 글자의 글꼴·크기·굵기·색, 링크·목록·문단 서식 |
| 본문 블록 메뉴 | 블록 추가·이동·삭제, 표 편집, 이미지 크기 |

본문에서 직접 지정한 서식이 전체 기본 서식보다 우선합니다. 본문을 하나의 문서로 재사용하는 것이 목적이므로 문단마다 별도 짭그마 컴포넌트를 만들지 않습니다. 외부 폰트 다운로드 없이 시스템 글꼴을 사용하며 명조 등 실제 표시 글꼴은 기기에 따라 달라질 수 있습니다.

## 첨부파일

**본문 편집**에서 `/image` 또는 `/file`을 입력하고 해당 블록을 선택한 뒤 **Add image / Add file → Upload**를 사용합니다. 별도 첨부 버튼은 두지 않습니다. `POST /api/files/upload?projectId=...`에 `file`과 **`category=tmp`**를 전달합니다. 서버가 세션·편집 권한·CSRF·파일 형식·크기를 확인하고 외부 file-service로 전송합니다. 패키지 기본 Base64 저장은 사용하지 않습니다.

본문 편집 창 안에서 `/` 메뉴·업로드 패널·서식 도구를 사용할 수 있도록 해당 에디터의 포털을 모달 내부에 연결합니다. 화면 아래쪽에서도 `/` 메뉴의 위·아래 방향키로 모든 항목을 이동할 수 있으며, 첫 항목에서 위 방향키를 누르면 마지막 Emoji 항목으로 이동합니다. 메뉴 높이가 달라져도 선택된 항목이 보이도록 높이와 목록 스크롤을 보정합니다. 이미지의 33%·50%·100%·원본 크기 메뉴에는 일반 페이지 버튼 스타일을 적용하지 않습니다.

- PNG/JPEG/GIF/WebP, PDF, TXT, CSV, JSON. 기본 최대 10 MB. SVG·HTML·실행 파일·동영상·음성 파일 업로드는 기존 정책상 지원하지 않습니다.
- 파일 서비스의 미리보기 준비(202)는 최대 5회 확인합니다. 실패·만료는 오류와 재확인 버튼으로 안내합니다.
- 외부 링크는 공개입니다. `tmp`의 정확한 보존 기간은 제공된 계약에 명시되어 있지 않으며 이 앱이 보관 기간을 연장하지 않습니다.
- 개인 템플릿 등록·다른 프로젝트 적용은 파일 ID와 권한 연결을 보존하지만 **파일 수명은 연장하지 않습니다**. 오래 재사용할 공식/개인 템플릿은 텍스트·표·자리표시자 중심 구성이 적합합니다.
- 직접 입력한 http(s) 이미지/미디어 URL은 앱의 CSP에서 허용한 주소만 표시할 수 있습니다. 프로젝트 업로드/보존 정책 및 내보내기 자산 복사 대상이 아니므로 파일 첨부 기능을 권장합니다.

## 저장과 내보내기

UI Spec의 `node.props.documentJson`에 BlockNote 문서 JSON 문자열을 저장합니다. 빈 본문은 `""`, 본문 하나당 UTF-8 **128 KB**입니다. HTML 저장·주입은 하지 않습니다. 문서 구조·중첩·표 크기·URL을 공통 명세에서 검증하고 API도 같은 검사를 사용합니다.

`richTextFiles`에는 `{fileId,name,mimeType}`를 저장합니다. 문서 안의 업로드 URL은 `jjapgma-file:파일ID`로 정규화합니다. 표시 시 이미지 준비 상태를 확인한 뒤 권한이 확인된 프로젝트/템플릿 content endpoint에서 읽어 임시 Blob URL로 표시하고 닫을 때 해제합니다. 이 방식은 외부 파일 호스트에 대한 브라우저 CSP를 완화하지 않습니다. 저장과 개인 템플릿 생성 시 참조 소유권·파일명·MIME을 확인합니다. 기존 `pages.spec`와 Revision/개인 템플릿 JSON을 사용하므로 신규 DB 마이그레이션은 없습니다.

HTML·Storybook ZIP은 **업로드한 본문 첨부파일을 assets에 포함**합니다. 만료되었거나 권한이 없는 파일은 내보내기가 실패합니다. 외부 URL은 그대로 남습니다. JSON 명세만 내보내면 파일 본문이 포함되지 않습니다.

**실제 서비스에서 새로 첨부하는 파일은 default 정책**을 사용합니다. React의 `Screen.richText` 또는 HTML의 `window.jjapgmaRichText`에 업로드·본문 변경 함수를 연결합니다. 이 경로는 `file`만 전달하며 `category`를 생략합니다. 소비 서비스의 백엔드도 category를 생략해야 합니다. 업무 저장·인증·파일 소유권 검사는 소비 서비스가 구현합니다. [연결 예제와 기존 tmp 파일 처리](RICH_TEXT_RUNTIME.md)는 ZIP에도 `RICH_TEXT.md`로 포함합니다.

Storybook 렌더러 빌드는 React를 외부 의존성으로 유지하면서 BlockNote의 CommonJS 하위 의존성을 [Rolldown 공식 내장 플러그인](https://rolldown.rs/builtin-plugins/esm-external-require)으로 ES import에 연결합니다. 기존 Vite가 사용하는 Rolldown 1.2.8을 개발 의존성으로 명시했으며 패키지 자체를 수정하지 않습니다.
